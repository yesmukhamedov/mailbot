# mailbot

Почта из терминала: несколько ящиков, точечная отправка, рассылка по списку и выгрузка входящих
для анализа. Стандартные протоколы там, где провайдер их пускает, браузер — там, где закрыл.

Инструмент вырос из практической задачи: в университетском тенанте Microsoft 365 админ не даёт
согласия на Graph API, и ни один нормальный почтовый клиент к ящику не подключается. Веб-почта в
браузере при этом работает. Отсюда идея — один интерфейс поверх разных способов добраться до
ящика, чтобы подключение второго и третьего ящика не превращалось в отдельный проект.

## Какой транспорт кому нужен

Проверено в августе 2026:

| Ящик | Что доступно | Транспорт |
|---|---|---|
| Gmail, Яндекс, Mail.ru, iCloud | пароли приложений, IMAP | `smtp-imap` — быстрый, ~секунда на письмо |
| Microsoft 365 (рабочая, учебная) | basic auth для IMAP отключён с 2022, для SMTP выключается в конце 2026; OAuth требует согласия администратора | `outlook-web` — браузер |
| Outlook.com, Hotmail, Live | пароли приложений отключены с сентября 2024, только OAuth | `outlook-web` — браузер |

Браузерный транспорт здесь не костыль на время, а постоянная часть: для Microsoft-ящиков без
помощи администратора другого пути нет. Но он — один из транспортов, а не устройство всей программы.

## Установка

```bash
git clone https://github.com/yesmukhamedov/mailbot.git
cd mailbot
npm install
```

Нужны Node.js >= 20.6 и — только для браузерного транспорта — установленный Chrome
(используется системный, отдельный браузер Playwright не скачивается).

## Подключение ящиков

Мастер задаст вопросы и запишет настройки:

```bash
node bin/mailbot.js account add
```

То же самое флагами, без вопросов:

```bash
# Gmail и подобные
node bin/mailbot.js account add --preset gmail --address me@gmail.com --name gmail

# рабочая почта Microsoft 365
node bin/mailbot.js account add --preset outlook --address me@university.edu --name work
node bin/mailbot.js login work        # откроется окно Chrome, пароль вводите вы

# личная почта Outlook.com
node bin/mailbot.js account add --preset outlook-personal --address me@outlook.com --name personal
node bin/mailbot.js login personal
```

Готовые провайдеры: `gmail`, `yandex`, `mailru`, `icloud`, `outlook`, `outlook-personal`, `custom`.
Для `custom` хосты SMTP и IMAP указываются вручную — см. `accounts.example.json`.

Ящиков может быть сколько угодно; какой использовать, выбирается флагом `--from`.

### Где лежат пароли

В `accounts.json` пароля нет — только имя переменной окружения:

```json
{ "type": "smtp-imap", "preset": "gmail", "address": "me@gmail.com", "passEnv": "MAILBOT_GMAIL_PASS" }
```

Сам пароль кладётся в `.env` (см. `.env.example`):

```
MAILBOT_GMAIL_PASS=абвгдеёжзийклмно
```

Для Gmail и Яндекса нужен **пароль приложения**, а не обычный пароль от аккаунта:
включите двухэтапную проверку, затем создайте пароль приложения в настройках безопасности.
Ящикам Microsoft пароль не нужен вовсе — там разовый `mailbot login`.

Ни `accounts.json`, ни `.env`, ни профили браузера в git не попадают.

### Проверка

```bash
node bin/mailbot.js doctor
```

Подключается к каждому ящику и печатает, что реально работает:

```
[OK ] work — outlook-web, me@university.edu (4.7 с)
        умеет: send, list
        чтение: ОК, писем видно: 1
```

Это первое, что стоит запустить, когда что-то перестало работать: провайдеры меняют домены и
политики без предупреждения, и лучше узнать об этом одной командой, чем посреди рассылки.

## Отправка

```bash
node bin/mailbot.js send --from work --to a@b.kz,c@d.kz \
  --subject "Тема" --body "Текст" [--dry-run]
```

`--dry-run` подготавливает письмо и показывает, что ушло бы, ничего не отправляя.
Для браузерного транспорта он ещё и делает скриншот черновика.

Длинное письмо удобнее держать в файле, чем в командной строке: `--body-file письмо.txt`
берёт тело как есть, с переводами строк.

**Вложения** — `--attach`, пути через запятую; работают в обоих транспортах:

```bash
node bin/mailbot.js send --from work --to prof@example.edu \
  --subject "Диссертация" --body-file письмо.txt \
  --attach D:\docs\отзыв.docx,D:\docs\том.pdf
```

Отсутствующий файл виден сразу, до подключения к ящику. Суммарный размер сверяется с
лимитом письма (25 МБ с учётом кодирования) — программа предупредит до отправки.
В браузерном транспорте файл кладётся в черновик и ожидается окончание загрузки на
сервер; на десятке мегабайт это занимает минуту-другую.

На больших файлах веб-Outlook спрашивает, вложить копию или поделиться ссылкой на
OneDrive. По умолчанию берётся копия; `--onedrive` выбирает ссылку — единственный
способ отправить одним письмом больше лимита в 25 МБ.

## Чтение и анализ входящих

```bash
node bin/mailbot.js read --from gmail --limit 50 --since 7d --unread --full
node bin/mailbot.js read --from all --table
node bin/mailbot.js read --from work --folder sentitems --json out.json
```

По умолчанию на выход идёт JSON с разделёнными полями — это и есть формат для анализа:

```json
{
  "from": "Tolganay T. Chinibayeva",
  "subject": "Актуализированная информация по справочнику",
  "date": "2026-08-15T07:48:00.000Z",
  "snippet": "Здравствуйте! на кафедре…",
  "unread": true
}
```

Папки: `inbox`, `sent` (`sentitems`), `drafts`, `archive`, `junk`, `trash`. Имена приводятся к
папкам провайдера по служебным признакам IMAP, поэтому `sent` работает и там, где папка называется
`[Gmail]/Отправленные`.

`--full` дополнительно вытягивает текст письма целиком (только `smtp-imap`).
`--from all` читает сразу все ящики; недоступный ящик попадёт в `errors`, а не обнулит выгрузку.

## Рассылка

Список получателей — CSV, где одна колонка называется `email` или `почта`, остальные становятся
переменными шаблона. Разделитель определяется сам, так что выгрузка из Excel в русской локали
(через `;`) читается без правки.

```csv
email,имя,организация,дата
ivanov@example.org,Иван Иванов,МУИТ,15 сентября
```

Шаблон — тема в front-matter, тело ниже:

```markdown
---
subject: Приглашение на семинар — {{организация}}
---
Здравствуйте, {{имя}}!

Приглашаем вас на семинар {{дата}}.
```

```bash
# посмотреть, что получится, ничего не отправляя
node bin/mailbot.js campaign --from gmail --list people.csv --template letter.md --dry-run

# отправить
node bin/mailbot.js campaign --from gmail --list people.csv --template letter.md
```

Перед отправкой печатается сводка: сколько получателей, какие колонки нашлись, каких переменных
не хватает, кому уже уходило раньше. Проблемные строки видны до отправки, а не на двухсотом письме.

**Журнал и дозапуск.** Каждая отправка сразу пишется строкой в `campaigns/<шаблон>--<список>.jsonl`.
Если прогон оборвался, повторный запуск той же команды продолжит с места обрыва и не отправит
письмо повторно тем, кто его уже получил. Отключается флагом `--no-resume`.

**Темп.** По умолчанию берётся лимит провайдера (Gmail — 20 писем в минуту, 500 в сутки).
Меняется флагом `--rate`. Если получателей больше суточного лимита, программа предупредит и
предложит разбить на дни: `--limit 500` сегодня, та же команда завтра — остальные уйдут дозапуском.

## Ограничения, о которых честнее знать заранее

1. **Рассылка через Microsoft-ящик медленная.** Браузеру нужны секунды на письмо даже при живой
   сессии; сотня адресов — это десятки минут. Для массовых писем берите SMTP-ящик, рабочий
   Microsoft оставьте для точечных.
2. **Суточные лимиты** упираются в ящик, а не в программу: у Gmail это около 500 писем в сутки.
   Для тысяч получателей нужен специализированный сервис рассылок, а не личный ящик.
3. **Письмо с вложением веб-Outlook отправляет только из «Черновиков».** В самой форме
   компоуза кнопка «Отправить» нажимается, ошибки нет, а письмо молча остаётся
   черновиком. Поэтому после нажатия программа проверяет папку «Черновики» и, найдя
   письмо там, отправляет его оттуда. Отчёт `SENT` означает, что черновик из папки
   пропал, а не что кнопка нажалась. Побочный эффект: сорвавшаяся отправка оставляет
   черновик, и его лучше удалить — иначе двойник с той же темой и тем же адресатом
   от программы неотличим.
4. **Разбор списка писем в веб-Outlook эвристический.** Разметка не отдаёт поля напрямую, поэтому
   отправитель, тема и дата вычисляются по структуре строки. Это покрыто тестами, но при
   очередном редизайне интерфейса может потребовать правки — вся логика в
   `src/transports/outlook-web.js`.
5. **Массовая рассылка с рабочего адреса** — вопрос политики вашей организации и репутации домена.
   Программа за вас его не решает.

## Что можно добавить

Интерфейс транспорта (`src/transports/`) специально оставлен расширяемым: у каждого транспорта есть
`capabilities()`, и команды спрашивают его, что поддерживается, вместо того чтобы падать в глубине.
Незанятые места, если захотите поучаствовать:

- **HTML-письма** — `nodemailer` это умеет, нужно провести флаг через шаблон и `send()`;
- **вложения в рассылке** — точечная отправка их уже умеет, `campaign` пока нет;
- **список исключений** — отписавшиеся и отскочившие адреса, пропуск при рассылке;
- **полное тело письма для веб-Outlook** — сейчас `fetch()` там не реализован;
- **транспорт OAuth** для тех, у кого администратор всё-таки дал согласие.

## Разработка

```bash
npm test            # тесты чистой логики: CSV, шаблоны, конфиг, журнал, разбор писем
```

Структура: `bin/mailbot.js` — CLI, `src/commands/` — команды, `src/transports/` — способы
добраться до ящика, `src/` — общая логика (конфиг, шаблоны, CSV, рассылка).

Старые команды первой версии (`node read.js`, `node send.js`, `node login.js`) остались обёртками
над новым ядром и работают по-прежнему.

## Безопасность

- **Профиль браузера — это доступ к ящику.** В `profiles/` лежат куки живой сессии; кто получил
  папку, тот читает и отправляет почту от вашего имени. Она в `.gitignore` — пусть там и остаётся.
- Пароли приложений живут только в `.env`, в `accounts.json` — лишь имена переменных.
- Пароль от Microsoft-ящика программе не передаётся вообще: вы вводите его сами в окне Chrome.
- Журналы рассылок содержат адреса живых людей и тоже не коммитятся.
